# React security

`react/no-dangerously-set-inner-html` blocks `dangerouslySetInnerHTML` in `.tsx` and
`.jsx`.

React escapes every interpolated value, which is why XSS is rare in a React app. This prop
is the one hole in that, and it is a complete one: the string is parsed as HTML, so
`<img src=x onerror=…>` executes on your origin with access to the session cookie,
`localStorage` and any token in it. That is account takeover, not a defacement.

```tsx
// wrong
<div dangerouslySetInnerHTML={{ __html: article.body }} />
```

The value does not have to come from an obvious attacker. The recurring sources are a CMS
field an editor pasted into, a translation string from a spreadsheet, a "rich text"
column written months ago by a user, and a Markdown-to-HTML conversion whose renderer
allows raw HTML passthrough. "It was sanitised when it was saved" is the stored-XSS shape:
the trust decision was made by whoever wrote the row, under whatever sanitiser config was
in place then.

## What to write instead

**Render it as text.** If the content is not meant to carry markup, this is the whole fix:

```tsx
<div>{article.body}</div>
```

**Model the structure.** If the content is a known set of blocks, store it as data and map
it to components. This also gives you styling and accessibility you cannot get from an
HTML blob:

```tsx
{article.blocks.map((block) => <Block key={block.id} {...block} />)}
```

**Render Markdown to elements, not to a string.** `react-markdown` produces React nodes
directly, so no HTML is ever parsed:

```tsx
<ReactMarkdown>{article.body}</ReactMarkdown>
```

Leave `rehype-raw` out. Adding it re-opens exactly the hole this rule closes.

**Sanitise at render, if you must have HTML.** Use a maintained sanitiser with an explicit
allow-list, in the component, every time it renders:

```tsx
const clean = useMemo(() => DOMPurify.sanitize(html, { ALLOWED_TAGS: ['p', 'a', 'strong', 'em', 'ul', 'li'] }), [html]);
```

Never do this for a user-uploaded SVG — SVG carries `<script>` and event handlers, and
sanitiser configs for it are routinely bypassed. Serve uploaded SVGs from a separate
origin as a download, or rasterise them.

## Waivers

Waivable, not overridable. A waiver is defensible when the HTML is generated by your own
code in the same request from a fixed template with no interpolated user input, or when
it is the output of a sanitiser call on the line above. Put the sanitiser and the render
in the same place so a later reader can see the guarantee, and say in your reply where
the string comes from and what cleans it.
